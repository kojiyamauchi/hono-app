# Codexからの実装引き継ぎ

Claude Codeの親セッション（Opus）として、Codexから受け取った設計を実装済みPRにする。PR公開後の独立レビューはCodexが担当する。

1. `CLAUDE.md` を読み、現在のブランチがCodexの指定した作業ブランチと一致し、`main` ではないことを確認する。その上で [implementerの入力契約](../../agents/implementer.md) を確認する。ブランチが一致しない場合や、設計判断が必要な不足や既存変更との衝突があれば、Codexに確認事項を返す。
2. PRの起点になる空コミットをリポジトリ規約に従って用意する。再開時は既存の起点を使う。
3. `Agent` ツールで `implementer` を明示的に起動し、入力契約を満たす依頼を渡す。子は実装・検証・コミットを担当する。子が停止した場合は、進捗と不足事項を確認し、合意済みの範囲で解決できるものは子へ戻す。追加の仕様判断が必要ならCodexへ返す。
4. 親のOpusが子のコミットと検証結果を読み、仕様との整合とリポジトリ規約を確認する。[PRレビューSkillの「コードレビューの実施」](../pr-review/SKILL.md#5-コードレビューの実施) から、ローカル差分に適用できる必須・推奨チェック項目とコミット粒度の観点だけを参照する。PR上のCI確認とレビュー投稿は、公開後にCodexが行う。
   1. 実装に修正必須の指摘があれば、Opusは前回の `implementer` のエージェントIDを指定して `SendMessage` で指摘と解消の確認条件を渡し、作業を再開させる。再開できない場合は、元の入力契約を満たす依頼に指摘と確認条件を加えて、`Agent` ツールで `implementer` を新たに起動する。
   2. `implementer` が修正・検証・コミットを行い、修正コミットと検証結果をOpusに返す。
   3. Opusは最新HEADの差分と検証結果を再レビューする。修正必須の指摘が残っていれば、再度 `implementer` に差し戻す。追加の仕様判断が必要な場合は、PR作成に進まずCodexに確認事項を返す。
5. 修正必須の指摘がすべて解消し、最終コミットで必要な検証がすべて通過したことをOpusが確認してから、Opusがpushして `[claude]: 関心事` の形式でPRを作成する。PR本文は [PRテンプレート](../../../.github/pull_request_template.md) に沿って記載する。関連Issue、`実DB検証`、公開状態、push後の追跡参照は `CLAUDE.md` に従う。再開時は同じブランチの既存PRを確認する。
6. CodexにはPR URL・関連Issue・ブランチ・HEAD SHAを返す。PR作成前に停止した場合は、最後に完了した工程と残作業を返す。
